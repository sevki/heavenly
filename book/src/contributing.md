# Contributing

## Versioning

All crates share the workspace version in the root `Cargo.toml`. The minor
version increases by one with each roadmap milestone (M1 = 0.1, M2 = 0.2,
M3 = 0.3, …). Patch versions fix bugs within a milestone. Record every
change in `CHANGELOG.md` under the version it ships in.

## Checks

Before opening a pull request, run the same checks CI does:

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test --workspace --all-features
RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps --all-features
cargo build -p heavenly-core -p heavenly-geo --no-default-features --target thumbv7em-none-eabihf
cargo run -p heavenly-diagrams && git diff --exit-code book/src/diagrams
mdbook build book
```

## Playground

`book/src/playground.md` runs `heavenly-viz` (in `viz/`) compiled to
WebAssembly. The physics belongs in `viz/src/lib.rs`, where it is
unit-tested natively. `book/src/playground/playground.js` only draws.
Build the module with `book/build-playground.sh`, then use `mdbook serve
book`; browsers will not load WebAssembly from `file://`. The `.wasm` is
built in CI and is not committed.

## Diagrams

The book's figures are SVG files generated by `diagrams/src/main.rs` from the
library itself. Edit the generator, not the SVGs. CI regenerates them and
fails if the committed files differ. The SVGs are inlined into pages with
`{{#include}}`, use `currentColor` and mdbook's theme variables, and must
contain no blank lines.

Code samples in this book are included from `heavenly-core/examples/` using
`{{#include}}` anchors. Add new samples there, not inline, so CI compiles and
runs them.

## Reference data

`heavenly-geo` validates against values generated by SOFA (pyerfa) and SPICE.
To regenerate them after changing the generator:

```sh
pip install pyerfa==2.0.1.5 spiceypy==8.4.0
mkdir -p kernels && cd kernels
curl -O https://naif.jpl.nasa.gov/pub/naif/generic_kernels/pck/pck00011.tpc
curl -O https://naif.jpl.nasa.gov/pub/naif/generic_kernels/lsk/naif0012.tls
cd .. && python3 heavenly-geo/tests/reference/generate.py kernels > heavenly-geo/tests/reference/data.rs
```

The `reference` workflow regenerates the file weekly and on changes to it, and
fails if the output differs from what is committed.
